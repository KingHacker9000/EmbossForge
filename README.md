# EmbossForge

### Artwork in. Matched embossing dies out.

Turn SVGs and images into coordinated **male + female 3D-printable embossing dies**, with printer-aware validation and a reusable 42 mm hand embosser.

## What it does

```text
                 artwork / height map
                         │
                         ▼
                ┌─────────────────┐
                │   EmbossForge   │
                └─────────────────┘
                    │         │
                    ▼         ▼
                 male STL   female STL
                    └────┬────┘
                         ▼
                 matched emboss pair
                         │
                         ▼
              reusable 42 mm hand press
```

EmbossForge keeps the two halves coordinated from one shared source. Paper thickness, XY clearance, Z accommodation, printer limits, orientation, height-map interpretation, and validation provenance remain explicit rather than hidden in a mesh.

## Physical status

**Proven:** a simple 16 mm matched butterfly pair was printed on a FlashForge Adventurer 5M / 0.4 mm nozzle and successfully embossed notebook paper.

**Failed and learned from:** the first 42 mm variable-depth Butterfly-M physical article was much too shallow and its female Z allowance double-counted paper thickness. It made essentially no useful mark. That failure is recorded rather than hidden; the pairing math and FDM relief defaults have since been corrected. See [docs/PHYSICAL_VALIDATION.md](docs/PHYSICAL_VALIDATION.md).

**Next variable-depth validation:** the current Adventurer 5M development recipe uses physically meaningful stepped heights of approximately **0 / 0.4 / 0.8 / 1.2 mm** and a small explicit female Z allowance. This corrected recipe is software/CAD validated but remains awaiting its next physical paper test.

**Press:** the primary press is now the curved V3 handheld lever embosser generated by `embossforge lever-press`. It uses the standard 42 mm keyed dies. Its CAD/kinematics are tested; full printed strength is still awaiting physical validation.

## Core capabilities

- binary one-height embossing from SVG/raster artwork
- variable-depth stepped or continuous embossing from true raster height maps
- deterministic shaded-reference → inspectable derived height-map conversion
- printer-aware positive/negative feature filtering
- male and female derived from one canonical printable master
- engagement validation as well as collision validation
- non-overridable mating/geometry failures
- separately overridable experimental paper-risk warnings
- keyed 42 mm interchangeable dies
- elegant full-size handheld lever press + tiny butterfly flexure tongs
- STEP/STL mechanical export and open/closed CAD checks
- CLI, Python API, Windows desktop packaging, and agent documentation

## Height-map semantics

For a true machine height map:

```text
white       = zero / flat die face
light gray  = shallow relief
dark gray   = deeper relief
black       = maximum relief
```

For the current 0.4 mm-nozzle FDM development path, stepped relief can intentionally map active tones to:

```text
0.00 mm   flat background
0.40 mm   shallow detail
0.80 mm   medium detail
1.20 mm   strongest detail
```

This avoids grayscale tiers that exist mathematically but collapse into only a fraction of a printable layer.

A metallic/AI-rendered image is **not** a true height map. Use `shaded-reference` only when EmbossForge must derive geometry from such a render. If you already have a clean authored machine height map, use `height-map` directly.

See [docs/RELIEF_MODE_SPEC.md](docs/RELIEF_MODE_SPEC.md) and [docs/IMAGE_INPUT_SPEC.md](docs/IMAGE_INPUT_SPEC.md).

## Quick start from source

Reference environment: Python 3.11.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e ".[cad,gui,dev]"

embossforge doctor
pytest -q
```

### Binary die

```powershell
embossforge die seal.svg `
  --paper copy `
  --profile profiles\flashforge_adventurer_5m.toml
```

### True variable-depth height map — current 0.4 mm nozzle starting point

```powershell
embossforge die Butterfly-M.png `
  --out build `
  --name Butterfly-M-v3 `
  --diameter 42 `
  --base 3 `
  --mode relief `
  --source-interpretation height-map `
  --relief-max 1.20 `
  --relief-min 0.40 `
  --relief-style stepped `
  --relief-levels 4 `
  --relief-zero-threshold 0.08 `
  --relief-quality draft `
  --paper copy `
  --clearance 0.20 `
  --extra-depth 0.03 `
  --profile profiles\flashforge_adventurer_5m.toml `
  --allow-risky
```

`--allow-risky` may acknowledge paper-risk heuristics; it still cannot bypass invalid mating geometry.

### Shaded reference

```powershell
embossforge die medallion-render.png `
  --mode relief `
  --source-interpretation shaded-reference `
  --relief-max 1.20 `
  --relief-min 0.40 `
  --relief-levels 4 `
  --paper copy `
  --profile profiles\flashforge_adventurer_5m.toml
```

Inspect the derived height map before spending filament on an interpreted reference.

## Generate the primary hand embosser

```powershell
embossforge lever-press --out build\lever-press
```

The V3 press exports:

```text
body.stl
lever.stl
upper_carriage.stl
upper_backing_cap.stl
+ matching STEP files
```

It accepts standard **42 mm × 3 mm keyed EmbossForge dies** and uses an M6 main pivot, M5 drive pin, and two small M3 cap screws. The curved shell is cosmetic/ergonomic while hidden guide surfaces preserve deterministic alignment. See [docs/HANDHELD_LEVER_PRESS.md](docs/HANDHELD_LEVER_PRESS.md).

The older rod-guided engineering prototype remains available via `embossforge mechanics`.

## Python / agent API

The CLI and desktop app use the same generator service:

```python
from pathlib import Path
from embossforge.config import adventurer_5m_profile
from embossforge.generator import DieGenerationRequest, generate_die
from embossforge.relief import ArtworkMode, ReliefSpec, ReliefStyle, SourceInterpretation

result = generate_die(
    DieGenerationRequest(
        artwork=Path("Butterfly-M.png"),
        output_root=Path("build"),
        paper_preset="copy",
        printer_profile=adventurer_5m_profile(),
        artwork_mode=ArtworkMode.RELIEF,
        source_interpretation=SourceInterpretation.HEIGHT_MAP,
        relief=ReliefSpec(
            max_relief_mm=1.20,
            min_relief_mm=0.40,
            style=ReliefStyle.STEPPED,
            levels=4,
        ),
        female_extra_depth_mm=0.03,
        allow_risky=True,
    )
)

print(result.male_stl)
print(result.female_stl)
print(result.validation.highest_severity.value)
```

Agents should read [AGENTS.md](AGENTS.md) and [docs/AGENT_API.md](docs/AGENT_API.md). Generated STL/STEP files are outputs, not the source of truth.

## Why matched-pair validation matters

A mathematically correct die can still fail after slicing. A thin male ridge may survive as one extrusion while its matching negative groove disappears. EmbossForge therefore canonicalizes printer-sensitive geometry before deriving both halves.

Variable-depth dies add another failure mode: a female can be **too deep**. Such a pair may be collision-free yet fail to emboss because paper is never forced against the female cavity. Current validation checks both accommodation and engagement.

## Safety

Printed press hardware can fail suddenly under load. Keep fingers away from the die gap, begin at low force, inspect pivots/stops before use, and wear eye protection during early mechanical tests.

Deep relief can crease or tear paper. `--allow-risky` acknowledges experimental paper-risk findings; it does not disable hard die-mating validation.
