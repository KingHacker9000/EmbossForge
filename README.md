## What it does

EmbossForge takes artwork such as a logo, monogram, bookplate, seal, wedding mark, or simple illustration and generates a matched embossing pair:

```text
             your artwork
                  │
                  ▼
       ┌────────────────────┐
       │    EmbossForge     │
       └────────────────────┘
            │          │
            ▼          ▼
       male die     female die
        .stl          .stl
            └────┬─────┘
                 ▼
            emboss paper
```

The female die is not just a naive inverted mesh. EmbossForge keeps **paper thickness, lateral clearance, relief depth, printer profile, and orientation** explicit so the result is reproducible.

## For most people: use the desktop app

The normal workflow is intentionally small:

1. **Choose artwork** — SVG, PNG, JPG, WEBP, BMP, or TIFF.
2. **Choose die size and paper** — sensible defaults are provided.
3. **Choose a printer profile** — currently optimized around the FlashForge Adventurer 5M.
4. **Generate matched die pair**.
5. Open the output folder and send the two STL files to your slicer.

A generated design folder contains:

```text
my_design_normalized.svg
my_design_male.scad
my_design_female.scad
my_design_male.stl
my_design_female.stl
my_design_manifest.json
```

The desktop app keeps advanced options hidden until needed. You do **not** need to understand OpenSCAD or CadQuery to create ordinary dies.

### Windows builds

The release pipeline produces:

```text
EmbossForge-Setup-Windows-x64.exe
EmbossForge-Windows-x64-portable.zip
```

The Windows bundle carries the OpenSCAD runtime used for STL generation, so release users do not need a separate Python/OpenSCAD setup.

## Physically validated

The core matched-die concept has been tested on real hardware.

On **2026-09-07**, a **16 mm butterfly** pair generated by EmbossForge was printed on a **FlashForge Adventurer 5M with a 0.4 mm nozzle** and successfully embossed ordinary notebook paper.

See [docs/PHYSICAL_VALIDATION.md](docs/PHYSICAL_VALIDATION.md) for the exact validation record.

The reusable cartridge and press are still prototype hardware and require continued fit, motion, and strength validation.

## Why EmbossForge is different

| Problem | EmbossForge approach |
| --- | --- |
| Custom dies are tedious to model | Generate both dies directly from artwork |
| Female geometry is easy to get wrong | Paper thickness and clearance are explicit |
| Random STL edits are hard to reproduce | Parametric source + manifest are preserved |
| Different printers need different fits | Printer profiles and calibration artifacts |
| A new design usually means more CAD work | One reusable press, interchangeable die cartridges |
| LLM agents often edit generated files blindly | `AGENTS.md` defines source-of-truth and validation rules |

## vNext: variable-depth grayscale relief

Current production behavior is intentionally **binary**: artwork either embosses at one relief height or remains flat. The next major artwork-engine extension is designed to use grayscale as a real height field.

That enables designs such as:

- a strong outer ring and softer inner ring;
- layered emblems with several emboss depths;
- stepped or continuous relief;
- shallow textures and radial patterns;
- intentionally aggressive relief when a user accepts paper-damage risk.

The feature is designed to be additive: **binary remains the default and existing commands keep their behavior**. Relief mode will be opt-in, printer-aware, reproducible, and accompanied by advisory printability/paper-risk analysis. Risk warnings may be overridden; impossible geometry such as a female cavity breaking through its base remains a hard error.

The accepted architecture, CLI/API contract, manifest schema v2 plan, desktop UX, validation model, and staged rollout are documented in **[docs/RELIEF_MODE_SPEC.md](docs/RELIEF_MODE_SPEC.md)**.

This section describes planned behavior, not a feature that is already physically validated.

## Quick start from source

Reference environment: **Python 3.11**.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e ".[cad,gui,dev]"

embossforge doctor
pytest -q
embossforge gui
```

A source checkout still needs OpenSCAD installed to render STL output. Packaged desktop builds bundle it.

## CLI

Power users, scripts, CI jobs, and agents can use the same backend from the command line:

```powershell
embossforge die examples\embossforge_mark.svg
```

Useful examples:

```powershell
# common paper presets
embossforge die seal.svg --paper copy
embossforge die seal.svg --paper premium
embossforge die seal.svg --paper cardstock

# exact size / paper thickness
embossforge die seal.png --diameter 42 --paper-thickness 0.18

# printer profile
embossforge die seal.svg --profile profiles\flashforge_adventurer_5m.toml
```

## Python / agent API

The desktop app and CLI both call the same generation service:

```python
from pathlib import Path
from embossforge.config import adventurer_5m_profile
from embossforge.generator import DieGenerationRequest, generate_die

result = generate_die(
    DieGenerationRequest(
        artwork=Path("seal.svg"),
        output_root=Path("build"),
        diameter_mm=42,
        paper_preset="copy",
        printer_profile=adventurer_5m_profile(),
    )
)

print(result.male_stl)
print(result.female_stl)
```

Coding and LLM agents should read [AGENTS.md](AGENTS.md) before changing the project. It documents repository structure, geometry invariants, tests, release commands, and the rule that **generated STL/STEP files are not the source of truth**.

More: [docs/AGENT_API.md](docs/AGENT_API.md)

## Small physical tests before large prints

Use the cheapest test that answers the current question:

```text
embossforge butterfly-test   tiny real emboss smoke test
embossforge fit-coupon       cartridge / receiver clearance
embossforge calibrate        emboss + clearance matrices
embossforge mini-test        reduced functional press
embossforge mechanics        full mechanical prototype
```

A miniature can validate geometry and motion. It does **not** certify a full-size printed press for load.

## Reusable press platform

EmbossForge is designed around **one press with interchangeable die cartridges**.

The current mechanical pack includes:

- printed base and side cheeks
- two smooth guide rods
- sliding upper platen
- universal upper/lower cartridge receivers
- keyed interchangeable die inserts
- lever with transverse contact roller
- physical stop sleeves
- M6-class main pivot and M5-class roller pin

`embossforge mechanics` generates the parametric mechanical package in `build/mechanics/` and checks open/closed printed-part collisions before accepting the assembly.

### Tool split

| Tool | Responsibility |
| --- | --- |
| Python | desktop UI, CLI, preprocessing, validation, orchestration |
| OpenSCAD | deterministic binary artwork relief and calibration geometry |
| CadQuery | parametric mechanical CAD and STEP/STL export |
| Blender | visual QA, assembly inspection, presentation |

Blender is useful for inspection and presentation, but it is **not** the dimensional source of truth.

Variable-depth relief may add a dedicated deterministic height-map/mesh backend if OpenSCAD is not efficient enough for dense relief surfaces. That does not change the binary-mode source-of-truth rules.

## Safety

The press is prototype hardware. Printed plastic can fail suddenly under load. Keep fingers away from the die gap, begin at low force, inspect pivots and stops before use, and wear eye protection during early mechanical testing.

Future variable-depth relief warnings are intended as experimental design heuristics, not guarantees that paper will not tear or puncture.
