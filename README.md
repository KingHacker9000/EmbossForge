# EmbossForge

[![CI](https://github.com/KingHacker9000/EmbossForge/actions/workflows/ci.yml/badge.svg)](https://github.com/KingHacker9000/EmbossForge/actions/workflows/ci.yml)

**Artwork in. Matched male/female embossing dies out.**

EmbossForge is an open-source system for creating 3D-printable paper embossing dies and a reusable interchangeable-die press. The project keeps artwork processing, fit parameters, and mechanical geometry reproducible instead of relying on hand-edited STL files.

## For most people: use the desktop app

You should not need Python, OpenSCAD, CadQuery, or a terminal just to create a die.

The EmbossForge desktop app provides a simple workflow:

```text
Drop SVG / PNG / JPG
        ↓
Preview design
        ↓
Choose die size + paper + printer
        ↓
Generate die files
        ↓
Male STL + Female STL
```

The UI keeps common choices visible and puts relief, margin, clearance, and artwork inversion under **Advanced settings**.

Official Windows release builds are designed to provide:

- **`EmbossForge-Setup-Windows-x64.exe`** — normal installer
- **`EmbossForge-Windows-x64-portable.zip`** — unzip and run `EmbossForge.exe`

The official Windows bundle includes its own OpenSCAD runtime, so binary-release users do not need to install Python or OpenSCAD separately.

See [`docs/DESKTOP_APP.md`](docs/DESKTOP_APP.md).

## Project status

The core die concept is **physically validated** on the target printer.

On 2026-09-07, a 16 mm butterfly male/female pair generated by EmbossForge was printed on a FlashForge Adventurer 5M with a 0.4 mm nozzle and successfully embossed ordinary notebook paper. See [`docs/PHYSICAL_VALIDATION.md`](docs/PHYSICAL_VALIDATION.md).

The reusable cartridge and press remain prototype hardware and still require physical fit, motion, and strength validation.

Current capabilities include:

- minimalist PySide6 desktop die generator
- drag/drop or file-picker artwork input
- SVG and raster artwork normalization
- raster-to-vector tracing
- normalization of tricky SVG coordinate origins
- automatic matched male/female dies
- paper presets and exact paper-thickness overrides
- printer-profile validation and clearance defaults
- keyed die carriers for deterministic orientation
- OpenSCAD source + STL + JSON manifest output
- low-filament smoke tests and calibration pieces
- parametric CadQuery cartridges, receivers, and lever press
- STEP/STL mechanical export
- generated assembly/hardware manifests
- open/closed solid collision checks
- Blender assembly import for visual QA
- GitHub Actions CI
- Windows portable/installer release workflow
- agent-oriented `AGENTS.md` and shared Python generation API

## Generate your own die in the desktop app

1. Drop/select an SVG, PNG, JPG, BMP, TIFF, or WEBP design.
2. Confirm the preview.
3. Choose die diameter, paper type, and printer.
4. Click **Generate die files**.
5. Open the generated output folder.

A normal design folder contains:

```text
<name>_normalized.svg
<name>_male.scad
<name>_female.scad
<name>_male.stl
<name>_female.stl
<name>_manifest.json
```

The STL pair goes into your slicer. The SCAD and manifest files make the result reproducible and inspectable.

## Run the desktop app from source

Reference development environment: Python 3.11.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e ".[cad,gui,dev]"

embossforge doctor
pytest -q
embossforge gui
```

A source checkout still needs OpenSCAD installed to render STL output. Official desktop bundles carry their own OpenSCAD runtime.

## CLI / automation

The CLI remains available for power users, scripts, CI, and LLM agents:

```powershell
embossforge die examples\embossforge_mark.svg
```

Paper presets:

```powershell
embossforge die my_logo.svg --paper copy
embossforge die my_logo.svg --paper premium
embossforge die my_logo.svg --paper cardstock
```

Exact override:

```powershell
embossforge die my_logo.png --diameter 42 --paper-thickness 0.18
```

Printer profile:

```powershell
embossforge die my_logo.svg --profile profiles\flashforge_adventurer_5m.toml
```

The female die is intentionally not an exact negative. EmbossForge accounts for paper thickness plus configurable lateral/depth clearance and installation orientation.

See [`docs/ARTWORK_GUIDE.md`](docs/ARTWORK_GUIDE.md).

## Python / agent integration

Desktop and CLI both call the same backend API:

```python
from pathlib import Path
from embossforge.config import adventurer_5m_profile
from embossforge.generator import DieGenerationRequest, generate_die

result = generate_die(
    DieGenerationRequest(
        artwork=Path("logo.svg"),
        output_root=Path("build"),
        paper_preset="copy",
        printer_profile=adventurer_5m_profile(),
    )
)

print(result.male_stl)
print(result.female_stl)
```

LLM/coding agents should read [`AGENTS.md`](AGENTS.md) before making changes. It documents the repository map, geometry invariants, validation commands, UI contract, release process, and when expensive GUI/3D-agent work is actually warranted.

## Tiny physically validated smoke test

```powershell
embossforge butterfly-test
```

Then load both STLs at 100% scale:

```text
build/butterfly-test/micro_butterfly_male.stl
build/butterfly-test/micro_butterfly_female.stl
```

This pair has already been physically demonstrated on the Adventurer 5M. See [`docs/FIRST_PRINT.md`](docs/FIRST_PRINT.md).

## Spend filament in the right order

EmbossForge provides progressively more expensive tests:

```text
embossforge butterfly-test   # tiny real emboss smoke test
embossforge fit-coupon       # tiny cartridge rail/receiver clearance test
embossforge calibrate        # clearance + emboss matrices
embossforge mini-test        # reduced functional press
embossforge mechanics        # full mechanical prototype
```

A successful miniature is not proof of full-size strength. Small prints validate geometry, fit, motion, and light embossing only.

## Mechanical platform

`embossforge mechanics` generates the current press pack in `build/mechanics/`.

The design currently uses:

- printed base and side cheeks
- two smooth steel guide rods
- sliding upper platen
- universal upper/lower cartridge receivers
- keyed interchangeable die inserts
- lever with a transverse contact roller
- physical stop sleeves
- M6-class main pivot and M5-class roller pin

Unique printed parts fit within the FlashForge Adventurer 5M build envelope. Exact hardware dimensions come from the generated `mechanics_manifest.json`.

The generator checks open and nominally closed CadQuery assemblies for unintended printed-part intersections before accepting the mechanical pack.

## Tool architecture

EmbossForge deliberately separates responsibilities:

- **`generator.py`** — shared desktop/CLI/API orchestration
- **Python** — UI, CLI, artwork processing, validation, presets, automation
- **OpenSCAD** — deterministic artwork relief and calibration geometry
- **CadQuery** — parametric mechanical CAD and STEP/STL exports
- **Blender** — visual QA, ergonomics, presentation, assembly inspection

Blender is not the dimensional source of truth. Generated meshes should not be hand-edited instead of correcting the parametric source.

## Windows release pipeline

`.github/workflows/release-windows.yml` builds a self-contained Windows desktop distribution with PyInstaller, bundles OpenSCAD, creates a portable ZIP, and wraps the same app in an Inno Setup installer.

Tagged `v*` builds can attach both packages directly to GitHub Releases. See [`docs/DESKTOP_APP.md`](docs/DESKTOP_APP.md) and [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

## Target printer

Primary development target:

- FlashForge Adventurer 5M
- 220 × 220 × 220 mm build volume
- 0.4 mm nozzle for current prototype development
- 0.25 mm nozzle planned for fine-detail work

Printer-sensitive tolerances are calibration values, not universal constants.

## Safety

The current press is prototype hardware. Printed plastic can fail suddenly under load. Keep fingers away from the die gap, begin with low forces, inspect pivots/stops before use, and wear eye protection during early mechanical testing.
