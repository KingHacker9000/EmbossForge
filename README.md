## What it does

EmbossForge takes a logo, monogram, bookplate, seal, wedding mark, grayscale height map, or shaded medallion-style reference and generates a matched embossing pair:

```text
             your artwork
                  │
                  ▼
       ┌────────────────────┐
       │    EmbossForge     │
       └────────────────────┘
            │          │
            ▼          ▼
       male die     female die
        .stl          .stl
            └────┬─────┘
                 ▼
            emboss paper
```

The female die is not a naive inverted mesh. EmbossForge keeps **paper thickness, lateral clearance, relief depth, printer limits, source interpretation, orientation, and validation provenance** explicit so the result is reproducible.

## Desktop workflow

1. **Choose artwork** — SVG, PNG, JPG, WEBP, BMP, or TIFF.
2. **Choose emboss style** — Simple one-height emboss or Variable depth.
3. For Variable depth, choose whether the raster is a **true height map** or a **3D-looking/shaded reference**.
4. Choose die size, paper, and printer profile.
5. Generate and review the pair-fit result.
6. For shaded references, EmbossForge first derives an inspectable relief preview. Accept that preview before final STL rendering.
7. Open the output folder and send the male/female STLs to the slicer.

Binary designs normally produce normalized SVG, male/female SCAD, male/female STL, and a JSON manifest. Relief jobs also preserve canonical machine height maps and relief surface maps. Shaded-reference jobs additionally preserve the derived height map, foreground mask, and preview used to create geometry.

The packaged Windows app bundles OpenSCAD. Source checkouts need OpenSCAD installed separately.

See [docs/DESKTOP_APP.md](docs/DESKTOP_APP.md).

## Validation status

**Physically validated:** on 2026-09-07, a 16 mm binary butterfly pair generated by EmbossForge was printed on a FlashForge Adventurer 5M with a 0.4 mm nozzle and successfully embossed ordinary notebook paper. See [docs/PHYSICAL_VALIDATION.md](docs/PHYSICAL_VALIDATION.md).

**Software/CAD validated:** variable-depth height-map generation, matched male/female derivation from one canonical field, paper/clearance allowances, printer-aware filtering, deterministic shaded-reference interpretation, schema-v2 manifests, and exported-STL nominal closure checks are implemented and covered by automated tests/CI.

**Still awaiting physical validation:** variable-depth depth quality, paper behavior across multiple relief levels, and the reusable cartridge/press hardware. Software should not present those as physically proven until measured test prints are recorded.

## Relief semantics

### True height maps

The machine convention is explicit. By default:

- white = zero relief
- black = maximum relief
- grayscale = intermediate relief

The polarity can be reversed. Relief can be stepped for FDM-friendly discrete levels or continuous for a smooth height field. Gamma, dead zone, smoothing, sampling quality, maximum depth, and printer-aware sub-resolution filtering are configurable.

### Shaded references

A metallic/AI/rendered image is **not** a true height map. EmbossForge's `shaded-reference` path therefore does not simply desaturate the image and call brightness depth. It deterministically isolates the motif, suppresses broad illumination, uses stable local structure and motif boundaries to synthesize emboss-oriented relief, writes that derived map to disk, and records the method in the manifest.

This is an **interpretation for embossing**, not a claim to reconstruct the source object's true 3D geometry. The desktop app requires the derived preview to be reviewed before final STL rendering.

See [docs/IMAGE_INPUT_SPEC.md](docs/IMAGE_INPUT_SPEC.md) and [docs/RELIEF_MODE_SPEC.md](docs/RELIEF_MODE_SPEC.md).

## CLI

Binary artwork remains backward-compatible and is still the default:

```powershell
embossforge die seal.svg --paper copy --profile profiles\flashforge_adventurer_5m.toml
```

True variable-depth height map:

```powershell
embossforge die relief.png `
  --mode relief `
  --source-interpretation height-map `
  --relief-max 0.35 `
  --relief-style stepped `
  --relief-levels 6 `
  --paper copy `
  --profile profiles\flashforge_adventurer_5m.toml
```

Shaded/rendered reference:

```powershell
embossforge die medallion.png `
  --mode relief `
  --source-interpretation shaded-reference `
  --relief-max 0.35 `
  --paper copy `
  --profile profiles\flashforge_adventurer_5m.toml
```

The CLI preserves the derived shaded-reference artifacts and provenance but, unlike the desktop UI, cannot visually approve the intermediate preview for you. Inspect the generated preview when using this mode in an automated workflow.

Artwork guidance: [docs/ARTWORK_GUIDE.md](docs/ARTWORK_GUIDE.md)

## Python / agent API

The desktop app and CLI call the same service:

```python
from pathlib import Path
from embossforge.config import adventurer_5m_profile
from embossforge.generator import DieGenerationRequest, generate_die
from embossforge.relief import ArtworkMode, ReliefSpec, SourceInterpretation

result = generate_die(
    DieGenerationRequest(
        artwork=Path("relief.png"),
        output_root=Path("build"),
        paper_preset="copy",
        printer_profile=adventurer_5m_profile(),
        artwork_mode=ArtworkMode.RELIEF,
        source_interpretation=SourceInterpretation.HEIGHT_MAP,
        relief=ReliefSpec(max_relief_mm=0.35),
    )
)

print(result.male_stl)
print(result.female_stl)
print(result.validation.highest_severity.value)
```

Agents should read [AGENTS.md](AGENTS.md). Generated STL/STEP files are outputs, not source of truth. More: [docs/AGENT_API.md](docs/AGENT_API.md).

## Small tests before large prints

```text
embossforge butterfly-test   tiny real binary emboss smoke test
embossforge fit-coupon       cartridge / receiver clearance
embossforge calibrate        emboss + clearance matrices
embossforge mini-test        reduced functional press
embossforge mechanics        full mechanical prototype
```

A miniature validates geometry and motion. It does not certify a full-size printed press for load.

## Reusable press platform

EmbossForge is designed around **one press with interchangeable die cartridges**. The mechanical pack includes printed base/cheeks, guide rods, sliding platen, universal upper/lower receivers, keyed inserts, lever/contact roller, stops, and M6/M5-class pivots. `embossforge mechanics` exports the parametric package and checks open/closed printed-part collisions before accepting the assembly.

### Tool split

| Tool | Responsibility |
| --- | --- |
| Python/OpenCV | desktop UI, CLI, preprocessing, height fields, validation, orchestration |
| OpenSCAD | binary relief, variable-height surface geometry, calibration, STL closure checks |
| CadQuery | parametric mechanical CAD and STEP/STL export |
| Blender | visual QA, assembly inspection, presentation |

Blender is useful for inspection and presentation, but it is **not** the dimensional source of truth.

## Safety

The press is prototype hardware. Printed plastic can fail suddenly under load. Keep fingers away from the die gap, begin at low force, inspect pivots and stops before use, and wear eye protection during early mechanical testing.

Paper-risk findings are experimental heuristics, not guarantees that paper will not tear or puncture. Hard geometry/mating failures are not bypassed by the paper-risk override.
